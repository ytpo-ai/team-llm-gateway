## 渠道用量感知与多渠道自动 Fallback（PROVIDER_USAGE_SENSE）

基于多渠道绑定能力，进一步实现渠道上游用量感知和自动 failover：gateway 查询上游渠道自身的用量/限额数据，转发时按优先级遍历候选渠道，跳过已耗尽渠道，429 自动标记并切换。

**完成事项**

- Provider Schema 新增 `usageEndpoint` 字段，标记上游用量查询 API URL。
- 新增 ProviderUsage Schema（Mongoose）：缓存上游用量快照（额度总量/已用/剩余、速率限制、耗尽状态）。
- 新增 ProviderUsageService：`fetchAndCache()` 查询上游、`getSnapshot()` 取缓存（TTL 30s）、`isExhausted()` 判尽、`markExhausted()` 标记耗尽、`updateFromHeaders()` 从响应头提取速率信息。
- UpstreamAdapter 接口扩展：新增 `ProviderUsageSnapshot` 类型 + 可选 `fetchUsage()` 方法。
- ProxyService 多渠道 fallback：`getProviderCandidates()` 按 priority 排序、`tryCandidate()` 检查可用性、`resolveModel()` 提取模型解析、`extractRateLimitHeaders()` 速率头提取。chatCompletions / streamChatCompletions / messages / streamMessages 四入口均支持 retry loop（429/5xx 自动切换）。
- 新增 `GET /usage/by-provider` 按渠道聚合 API，关联 Provider.name 补全展示名。
- 前端用量看板增加"按渠道"拆分卡片（2×2 网格）。
- 前端渠道管理页增加"用量探测"列。
- 验证：后端 lint / typecheck / test（218 passed）；前端 build 全通过。

# 团队管理功能的优化建议

首先我们已确定的系统有两种模式
1. 团队自部署运营模式
2. SaaS模式

【团队自部署运营模式】下，项目创建默认团队，原则上【团队自部署运营模式】下是公司用来管理内部团队小组，【SaaS模式】下是服务商来管理客户团队，两种模式下都需要分为【系统管理员】和【团队管理员】角色，只有【系统管理员】有创建团队的权限，【系统管理员】创建团队后，可邀请【团队管理员】，正常由【团队管理员】进行团队的日常管理，当然，【系统管理员】也具备【团队管理员】所具备的所有能力，但从职责上来说，不应该由【系统管理员】直接管理团队。

在系统中，团队成员对应现实团队的员工，但员工并不需要登录系统做任何操作，系统的设计核心主要是可以以 团队/员工/apikey 三个级别进行LLM Token 日/周/月使用额度的限制，不同渠道的使用权限和额度限制，使用情况概览等

所以添加成员 只需要添加 成员名 作为员工标记，可选是否添加邮箱，有员工详情页，详情页中有对员工的各种设置以及使用概览

为了方便对员工的设置，我们默认以角色来设置，比如团队中的 设计师和开发人员 有不同的额度和渠道配置，系统中将根据一般经验内置几个常用角色模版帮助团队快速设置。

---

## 讨论结论（已定稿）

> 讨论时间：2026-11-02。以下为各优化项的最终决策，作为后续开发 plan 的依据。

### 1. 成员模型（不分离账号）

- 成员与登录账号**不拆分**，统一由 `User` 承载。
- `User.passwordHash` 改为**可选**：设置了密码才能登录，未设置密码的成员仅作员工标记，不可登录。
- `User.email` 改为**可选**：成员可不填邮箱。
- `{ tenantId, email }` 唯一索引改为 **partial/sparse 索引**（仅对非空 email 唯一）。

### 2. 两层角色体系

| 层 | 名称 | 是否固定 | 掌管字段 | 说明 |
|---|---|---|---|---|
| 角色A（管理范围） | 系统管理员 / 团队管理员 / 普通成员 | **固定** | `User.role`（RBAC） | 决定「谁能做管理操作」 |
| 角色B（LLM 使用限制） | 设计师 / 开发人员 … | **不固定** | `User.roleTemplateId` | 决定「能用哪些渠道/多少额度」 |

- 角色A 收敛为 3 个固定值：`system` / `team_admin` / `member`。
- **彻底废弃** `finance` / `viewer` / `provider`（清理枚举、守卫、测试、文档）。
- 角色B 由独立实体 `RoleTemplate` 承载，系统配置管理，内置常用模板（可增删改，内置不可删）。
- 一个用户**同时具备角色A + 角色B**。

### 3. 系统管理员（system）

- 单团队自部署模式下 `system` 角色**可见**（首个注册者为系统管理员）。
- 权限层级：`system > team_admin > member`。
- 只有 `system` 能创建团队、邀请团队管理员；团队日常管理由 `team_admin` 负责。
- 「system 具备 team_admin 全部能力但不直接管团队」采用**软约束**：技术上不拦截，仅 UI 引导走「建团队 → 指派团队管理员」。

### 4. 三级限额模型

- **余额账户**：仅团队（team）/ 成员（member）两级（沿用现有扣费逻辑：成员优先扣、团队兜底）。
- **限额（Limit，日/周/月）**：团队 / 成员 / apikey 三级各自设置，**实际生效值 = min(团队, 成员, key)**。
- **apikey**：只设限额 + 模型/渠道白名单，**不持余额**。
- **成员限额**：继承角色B 模板默认值；本期**不支持**单成员覆盖，数据模型预留 override 扩展点。
- **渠道级**：团队 / 成员 / key 三级的渠道访问白名单（渠道 = Provider）。

### 5. 角色B（RoleTemplate）字段

```
RoleTemplate {
  name                 // 设计师 / 开发人员
  description
  limitDaily           // 日 token 上限
  limitWeekly          // 周 token 上限
  limitMonthly         // 月 token 上限
  rateLimitPerMinute   // 每分钟速率
  providerIds          // 可用渠道白名单（渠道 = Provider）
  modelWhitelist       // 可用模型白名单（可选）
  builtIn              // 是否内置（内置不可删）
}
```

> 先跑通再优化，字段暂定如上。

### 6. 菜单结构

- 新增「团队管理 → 角色管理」（= 角色B `RoleTemplate` 管理页）。
- 新增「状态观察 → 使用日志」分页明细接口（`UsageLog` 已存在，缺单笔分页列表）。
- 其余菜单项映射现有能力（成员管理 / API Key / 渠道 / 模型 / 用量观察 / 操作日志 / 系统设置）。
- 详见 `docs/issue/菜单优化.md`。
